# 15 分钟生活圈 · 使用说明

「15 分钟生活圈」帮助你从任意一个中心点出发，理解步行可达范围、周边民生设施分布以及可能存在的服务缺口。本文档面向使用者，介绍如何上手、各功能入口和使用时需要注意的事项。

> 核对日期：2026-10-11，对应体检契约 `checkup-v1`、设施目录 `poi-categories-v2.3`。
> 本文写的是**本机运行的体检工作台**；发布站上的「离线 Demo」用的是固定模拟数据，两者不要混读。

---

## 一、这个工具能做什么

- **查看步行生活圈**：从中心点出发，基于真实步行路网展示 15 分钟内可以到达的范围，而不是简单画一个圆。
- **核对民生设施**：按类别查看民生设施的位置与名称。目录共 **10 个大类、31 个检索小类**，默认体检核心三类（购物、医疗、教育），其余按需补查。
- **生成体检报告**：把分析条件、结果、未知部分、数据来源和限制整理成一份可复核的报告。

**需要记住的边界**：单个中心点的结果不能代表整个社区；设施数量不代表容量、质量或营业状态；工具不会自动生成综合评分。

## 三、开始使用

### 方式一：双击启动脚本（最简单，推荐）

前提：已安装 Python 3.11 或更高版本，以及 Node.js `^20.19.0 || >=22.12.0`（20.x 需 20.19.0 以上，22.x 需 22.12.0 以上）。虚拟环境、pip 与 npm 依赖、`.env` 配置文件都由启动脚本自动准备，不需要手动执行 `pip install` 或 `npm install`。

**1. 取得源码并进入项目根目录**

```bash
git clone https://github.com/PennEwan/Baidu-map.git
cd Baidu-map
```

**2. 双击启动器**

- Windows：双击 `start.bat`
- macOS：双击 `start.command`
- Linux：在终端执行 `./start.command`

**3. 按提示填写百度地图 AK**

启动器会依次完成环境预检、生成配置文件、检查环境变量、确认运行模式、安装依赖五件事。遇到空的变量时，它会告诉你**写在哪、为什么需要、从哪拿**，再让你选择回车填写或按 `s` 跳过。

两个变量都可以跳过，但结果不一样：

- 跳过**服务端** AK（`backend/.env` 的 `BAIDU_MAP_AK`）会退回离线 `synthetic` 模式：E8.2 只画半径约 1080 米的正圆，设施检索、服务覆盖与路线核验都不运行。
- 跳过**浏览器端** AK（`life-circle-demo/.env.local` 的 `VITE_BAIDU_MAP_AK`）**不会**退回示意图：底图显示「地图不可用」，选中点仍可手动输入坐标继续体检。本地示意图只出现在显式的 `demo` 模式页面，而启动器打开的是体检工作台。

**4. 等待就绪，浏览器自动打开**

前后端都起来后浏览器会自动打开 `http://127.0.0.1:5173/`，后端在 `http://127.0.0.1:8000`，`/health` 可查状态。按 **Ctrl+C** 一次同时停止前后端。

> 启动器只是薄薄一层封装，内部调用 `python dev.py`。需要更细的控制时：

```bash
python dev.py setup           # 只做环境准备，不启动服务
python dev.py doctor          # 只体检：版本、依赖、变量、端口，缺什么报什么
python dev.py backend         # 只启动后端
python dev.py frontend        # 只启动前端
```

#### 关于 OSM 路网数据（可选组件）

OSM（OpenStreetMap）步行路网用于服务覆盖和 OSM＋百度分析。`dev.py` 只负责依赖、环境和服务启动；地区包的下载、构建和激活统一由 `setup_osm_region.py` 处理。运行包的来源、下载参数和各命令的详细用法，见 [OSM 路网数据下载说明](./OSM路网数据下载说明.md)。

拿到部署方提供的运行包 ZIP 时，一条命令即可下载、校验、解压并激活（ZIP 需包含 `data/osm/manifest.json`）：

```bash
python backend/scripts/setup_osm_region.py download --url <runtime-package-url> --region <region-id> --sha256 <archive-sha256>
```

已经解压到本地时，查看并激活地区包：

```bash
python backend/scripts/setup_osm_region.py list
python backend/scripts/setup_osm_region.py select --region <region-id>
```

选择器会校验图缓存、覆盖边界、数据版本和米制 CRS，并写入 `backend/.env`。暂时不使用 OSM 时执行：

```bash
python backend/scripts/setup_osm_region.py clear
```

> **这些脚本在主仓库里。** `backend/scripts/setup_osm_region.py`、`configure_osm_region.py`、`backend/app/osm_package.py` 与 `backend/docs/OSM_REGION_SETUP.md` 随主仓库提供；如果你的检出里没有它们，先更新到最新 `main`，或向维护者确认该版本是否已包含这些工具。

| 功能 | 没有路网数据时 |
| --- | --- |
| 百度边界搜索（E8.2）成圈 | 照常 |
| 设施检索、实测路线核验、报告 | 照常 |
| 1000 米服务覆盖、灰区清单、服务覆盖热力 | 标为「未评估」，**不会写成 0** |
| OSM＋百度 | 有服务端 AK 但没有地区包时仍可提交，结果标为「部分证据」；连服务端 AK 都没有（或合成模式）时，提交会在建立任务**之前**被具名拒绝，不会静默改成 E8.2 |

如果没有选择路网包，应用仍会启动基础功能；依赖 OSM 的结果会标为「未评估」或「部分证据」，不会把缺少数据写成 0。路网数据版本、投影 CRS、图缓存和覆盖边界必须来自同一个地区包，否则 OSM＋百度会降级。


> 路网数据版本、投影 CRS、图缓存和覆盖边界必须匹配；没有地区包时，OSM＋百度不会把未知区域当成没有设施或不可达。

路网数据来自 OpenStreetMap contributors，按 [Open Database License（ODbL）](https://opendatacommons.org/licenses/odbl/1-0/) 提供。使用或再分发数据时请保留 `© OpenStreetMap contributors` 署名；项目代码与 OSM 数据使用不同的许可证。该数据是固定快照，不代表实时道路状态，也不保证包含所有门禁、校园通道和小区内部道路。

### 方式三：手动启动本地分析服务

启动脚本失败或需要完全自己控制环境时，按下面的步骤分别启动后端和前端。

**1. 申请百度地图 API**

访问百度地图开放平台：https://lbsyun.baidu.com/

1. 使用百度账号登录，完成开发者认证（个人或企业）。
2. 进入「控制台」→「应用管理」→「我的应用」，点击「创建应用」。
3. 填写应用信息：
   - **应用名称：** 自定义，如「15分钟生活圈」。
   - **应用类型：** 选择「浏览器端」。
   - **启用服务：** 勾选「浏览器端AK」及所需的 Web 服务 API。
   - **安全配置（白名单）：** 填写允许访问的域名或 IP，开发阶段可填 `*` 表示不限制。
4. 创建完成后，在「我的应用」列表中可以查看并复制 AK。

> AK 相当于账号凭证，请勿提交到公开仓库或分享给他人。如怀疑泄露，请在控制台重置。

**2. 配置环境变量**

后端与浏览器用**两个不同的 AK**，写进两个文件（都可以用环境变量临时覆盖）：

| 变量 | 用在哪 | 写在哪里 | 注意 |
| --- | --- | --- | --- |
| `BAIDU_MAP_AK` | 服务端步行路线与地点检索 | `backend/.env` | 服务端密钥；不得放进前端，也不得入库 |
| `VITE_BAIDU_MAP_AK` | 浏览器底图与地图选点 | `life-circle-demo/.env.local` | 浏览器端 AK；需在控制台配置来源白名单 |

下面以后端变量为例：

```bash
# Windows CMD
set BAIDU_MAP_AK=你的百度AK

# Windows PowerShell
$env:BAIDU_MAP_AK="你的百度AK"

# macOS / Linux (bash/zsh)
export BAIDU_MAP_AK="你的百度AK"
```

以上命令仅在当前终端会话有效。如需永久配置，请按以下方式操作：

- **Windows：** 右键「此电脑」→ 属性 → 高级系统设置 → 环境变量 → 新建系统变量，变量名 `BAIDU_MAP_AK`，变量值填入你的 AK。
- **macOS：** 编辑 `~/.zshrc`（或 `~/.bash_profile`），添加 `export BAIDU_MAP_AK="你的百度AK"`，然后执行 `source ~/.zshrc`。
- **Linux：** 编辑 `~/.bashrc`（或 `~/.profile`），添加 `export BAIDU_MAP_AK="你的百度AK"`，然后执行 `source ~/.bashrc`。

修改后需要重新打开终端或重启编辑器才会生效。

浏览器端 AK 是另一个变量、另一个文件：在 `life-circle-demo/.env.local` 里写 `VITE_BAIDU_MAP_AK=你的浏览器端AK`（该文件不入库）。`VITE_*` 变量在构建时注入，改完要重启开发服务器或重新构建才生效；**不要把服务端步行 AK 写进这个变量**，它会被打包进浏览器代码。

**3. 高级用法：自行构建 OSM 路网数据（普通用户无需执行）**

后端读的是 `setup_osm_region.py` 生成的图缓存（例如 `data/osm/regions/<region-id>/<region-id>.osm-cache`），不是 OSMnx 的 `.graphml`。需要自定义地区或重建数据时，先从对应 Geofabrik 页面下载 `.osm.pbf` 与 `.poly`，安装一次构图依赖，再执行一条构建命令：

```bash
python -m pip install -r backend/requirements-osm-build.txt
python backend/scripts/setup_osm_region.py build --region <region-id> --pbf <path-to-pbf> --coverage <path-to-poly> --version <snapshot-id> --metric-crs <metric-crs> --source <pbf-url> --downloaded-at <yyyy-mm-dd>
```

该命令会生成图缓存、风险层、障碍层和 `manifest.json`，完成校验并直接激活地区；不再需要手动设置多项 OSM 环境变量、分别运行三个脚本或手工补 manifest。`--no-simplify` 可用于排查构图问题，重建已有地区时追加 `--force`。

> 手动构建得到的路网数据也应记录来源、快照版本和 SHA256，并保留 OSM/ODbL 署名。路网数据不进版本库。选好地区包后，后端会在**服务启动时后台预热**这份路网（`/health` 先报 `loading`，就绪后转为 `ready`），这样第一次体检就不必再等构图；没有地区包时评估阶段标为「未评估」，不会写成 0。

**4. 创建并激活虚拟环境**

建议使用 Python 虚拟环境隔离后端依赖：

```bash
# Windows CMD
python -m venv .venv
.venv\Scripts\activate.bat

# Windows PowerShell
python -m venv .venv
.venv\Scripts\Activate.ps1

# macOS / Linux (bash/zsh)
python3 -m venv .venv
source .venv/bin/activate
```

激活后终端提示符前会出现 `(.venv)` 标识。如需退出虚拟环境，执行 `deactivate`。

**5. 启动后端与前端**

```bash
# 后端（在虚拟环境中）
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 前端（新开终端，无需虚拟环境）
npm install
npm run dev
```

**6. 在浏览器中打开**

访问终端提示的地址（通常为 `http://localhost:5173`），即可进入分析工作台。

## 四、操作流程

### 第 1 步：选择分析位置

使用预设样例、在地图上选点，或手动输入经纬度。请确认本次分析从哪个中心点开始。

> 坐标是 **BD09LL**（百度坐标），**经度在前、纬度在后**，与报告里写明的坐标系一致；经度范围 −180～180，纬度 −85～85。演示页的坐标输入标着「演示坐标」，口径相同，但它只用于模拟数据。

### 第 2 步：查看步行生活圈

在地图上查看 15 分钟可达范围、已知可达区域、未知区域和计算质量。沿步行路网行进，绕行与硬约束都会被保留。

### 第 3 步：核对民生设施

按类别查看设施：目录共 10 个大类、31 个检索小类，默认体检核心三类（购物、医疗、教育）。列表按直线距离排序、可点选查步行路线；**是否算「在服务范围内」以返回的步行路线距离为准**，不是直线距离。检索失败、分页截断和「附近确实没有」是三种不同状态，界面不会把它们都写成 0。

### 第 4 步：生成体检报告

汇总条件、结果、服务缺口、未知部分、数据来源和限制说明，方便复核与分享。

## 五、如何理解结果

**15 分钟圈与 1 公里判断是两套独立指标**

- 15 分钟圈：按**步行路网**回答「15 分钟能走到哪里」，阈值 900 秒。
- 1 公里判断：同样按**步行距离**回答「周边是否存在某类设施」，标准是步行路线 1000 米（含 100 米容差带）。

两者用的是同一张步行路网，区别是**时间**与**距离**两种口径，所以不能互相换算，也不能互相替代。直线距离只用来给候选设施排序，不用来下结论。

**「未知区域」是什么意思**

当某方向数据不足、计算预算停止或服务异常时，地图会保留为「未知」，而不会静默标记为不可达。详情可在报告的结果说明中查看。

**结果的可信度边界**

- Demo 是可操作的模拟数据演示，用于验证流程一致性，不代表真实结论。
- 数据不足、部分结果、预算停止和服务异常都会保留状态。
- 覆盖率给出的是**区间**（下界～上界）：未知面积进入上界，不会被当成 0；业务状态最高为「部分证据」（`partial`），因为设施目录尚未经过独立核验。
- 单点分析不等于全社区评价。

## 六、常见问题

**Q：为什么有些按钮点了没反应？**
A：发布站上的外部入口在未配置时会被禁用（按钮变灰、不跳转），不会显示占位文案。本站的三个链接都已配置；本机运行时对应的入口由启动器读取的变量决定。

**Q：为什么报告里的覆盖率是一个区间，业务状态又是「部分证据」？**
A：覆盖率的下界～上界来自已评估面积与未知面积：未知部分计入上界，不当成 0。「部分证据」说的是证据的性质——目录尚未经独立核验，也可能有缺页，所以成功跑完也不会标成「完整」。

**Q：为什么地图上有些地方是空的？**
A：这些是未知区域，表示该方向缺少足够数据，并不代表不可达。

**Q：可以用手机操作吗？**
A：介绍页可以手机浏览，但完整分析建议在桌面浏览器中进行，以获得更好的地图交互体验。
