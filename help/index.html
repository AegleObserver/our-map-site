概述

「15 分钟生活圈」帮助你从任意一个中心点出发，理解步行可达范围、周边民生设施分布以及可能存在的服务缺口。本文档面向使用者，介绍如何上手、各功能入口和使用时需要注意的事项。

发布站本身是纯静态页面，不依赖后端即可独立访问；完整分析功能需要另行启动后端与前端服务。

环境要求

项目要求
操作系统Windows 10/11、macOS 12+、主流 64 位 Linux
Node.js20 或更高版本（发布站与前端）
Python3.11 或更高版本（分析后端与启动脚本）
浏览器Chrome / Edge / Firefox 近两年稳定版
磁盘空间发布站约 50 MB；完整分析工具建议预留 2 GB
内存建议 8 GB 及以上（分析工具）

运行完整分析工具时还需要：

  • Python 3.11 或更高版本
  • Git（可选，用于克隆源码）
  • 百度地图开放平台账号（申请 API Key）

开始使用

方式一：双击启动脚本（最简单，推荐）

前提：已安装 Python 3.11 或更高版本、Node.js 18 或更高版本。虚拟环境、pip 与 npm 依赖、.env 配置文件都由启动脚本自动准备，不需要手动执行 pip install 或 npm install。

1. 取得源码并进入项目根目录

git clone https://github.com/PennEwan/Baidu-map.git
cd Baidu-map

2. 双击启动器

  • Windows：双击 start.bat
  • macOS：双击 start.command
  • Linux：在终端执行 ./start.command

3. 按提示填写百度地图 AK

启动器会依次完成环境预检、生成配置文件、检查环境变量、确认运行模式、安装依赖五件事。遇到空的变量时，它会告诉你写在哪、为什么需要、从哪拿，再让你选择回车填写或按 s 跳过。

两个变量都可以跳过：跳过服务端 AK 后会退回离线 synthetic 模式（只画半径约 1080 米的正圆，不调用百度），跳过浏览器端 AK 后前端底图回退到本地示意图。

4. 等待就绪，浏览器自动打开

前后端都起来后浏览器会自动打开 http://127.0.0.1:5173/，后端在 http://127.0.0.1:8000，/health 可查状态。按 Ctrl+C 一次同时停止前后端。

启动器只是薄薄一层封装，内部调用 python dev.py。需要更细的控制时：

python dev.py setup           # 只做环境准备，不启动服务
python dev.py doctor          # 只体检：版本、依赖、变量、端口，缺什么报什么
python dev.py backend         # 只启动后端
python dev.py frontend        # 只启动前端

方式二：在线 Demo（推荐新用户）

  1. 打开首页，点击「打开 Demo」进入演示环境。
  2. Demo 使用固定模拟数据，用于快速体验完整流程，不代表真实社区结论。

方式三：手动启动本地分析服务

启动脚本失败或需要完全自己控制环境时，按下面的步骤分别启动后端和前端。

1. 申请百度地图 API

访问百度地图开放平台：https://lbsyun.baidu.com/

  1. 使用百度账号登录，完成开发者认证（个人或企业）。
  2. 进入「控制台」→「应用管理」→「我的应用」，点击「创建应用」。
  3. 填写应用信息：
    • 应用名称：自定义，如「15分钟生活圈」。
    • 应用类型：选择「浏览器端」。
    • 启用服务：勾选「浏览器端AK」及所需的 Web 服务 API。
    • 安全配置（白名单）：填写允许访问的域名或 IP，开发阶段可填 * 表示不限制。
  4. 创建完成后，在「我的应用」列表中可以查看并复制 AK。

AK 相当于账号凭证，请勿提交到公开仓库或分享给他人。如怀疑泄露，请在控制台重置。

2. 配置环境变量

# Windows CMD
set BAIDU_MAP_AK=你的百度AK

# Windows PowerShell
$env:BAIDU_MAP_AK="你的百度AK"

# macOS / Linux (bash/zsh)
export BAIDU_MAP_AK="你的百度AK"

以上命令仅在当前终端会话有效。如需永久配置：

  • Windows：右键「此电脑」→ 属性 → 高级系统设置 → 环境变量 → 新建系统变量，变量名 BAIDU_MAP_AK，变量值填入你的 AK。
  • macOS：编辑 ~/.zshrc（或 ~/.bash_profile），添加 export BAIDU_MAP_AK="你的百度AK"，然后执行 source ~/.zshrc。
  • Linux：编辑 ~/.bashrc（或 ~/.profile），添加 export BAIDU_MAP_AK="你的百度AK"，然后执行 source ~/.bashrc。

3. 准备 OSM 路网数据

使用 OSM 方案前，需要先在本地下载目标区域的路网数据。推荐使用 OSMnx 自动下载：

import osmnx as ox

# 按城市名称下载
graph = ox.graph_from_place("上海市青浦区", network_type="walk")
ox.save_graphml(graph, "data/roads.graphml")

# 或按经纬度范围下载
graph = ox.graph_from_bbox(31.25, 31.20, 121.50, 121.45, network_type="walk")
ox.save_graphml(graph, "data/roads.graphml")

也可以从 OpenStreetMap 官网或 Geofabrik 下载 .osm 或 .pbf 文件，放入 data/ 目录。

路网数据文件较大，建议只下载分析所需的区域，避免占用过多磁盘空间。

4. 创建并激活虚拟环境

建议使用 Python 虚拟环境隔离后端依赖：

# Windows CMD
python -m venv .venv
.venv\Scripts\activate.bat

# Windows PowerShell
python -m venv .venv
.venv\Scripts\Activate.ps1

# macOS / Linux (bash/zsh)
python3 -m venv .venv
source .venv/bin/activate

激活后终端提示符前会出现 (.venv) 标识。如需退出虚拟环境，执行 deactivate。

5. 启动后端与前端

# 后端（在虚拟环境中）
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 前端（新开终端，无需虚拟环境）
npm install
npm run dev

6. 在浏览器中打开

访问终端提示的地址（通常为 http://localhost:5173），即可进入分析工作台。前端开发服务器会代理后端请求，确认后端已在 :8000 端口运行。

操作流程

第 1 步：选择分析位置

使用预设样例、在地图上选点，或手动输入经纬度。请确认本次分析从哪个中心点开始。手动输入坐标时使用 WGS84 坐标系，注意顺序为纬度在前、经度在后。

第 2 步：查看步行生活圈

在地图上查看 15 分钟可达范围、已知可达区域、未知区域和计算质量。沿步行路网行进，绕行与硬约束都会被保留。

第 3 步：核对民生设施

按类别筛选菜市场、药店、小学等设施，查看名称、位置、是否在圈内以及来源证据。

第 4 步：生成体检报告

汇总条件、结果、服务缺口、未知部分、数据来源和限制说明，方便复核与分享。

如何理解结果

15 分钟圈与 1 公里判断是两套独立指标

  • 15 分钟圈：基于步行路网，回答「能走到哪里」。
  • 1 公里判断：基于直线距离，回答「周边是否存在某类设施」。

两者不会相互替代，请勿混用。

「未知区域」是什么意思

当某方向数据不足、计算预算停止或服务异常时，地图会保留为「未知」，而不会静默标记为不可达。详情可在报告的结果说明中查看。

结果的可信度边界

  • Demo 是可操作的模拟数据演示，用于验证流程一致性，不代表真实结论。
  • 数据不足、部分结果、预算停止和服务异常都会保留状态。
  • 单点分析不等于全社区评价。

常见问题

为什么有些按钮点了没反应？

对应的外部入口尚未配置，页面会显示「待配置」。请联系项目维护者或参考部署说明完成配置。

为什么地图上有些地方是空的？

这些是未知区域，表示该方向缺少足够数据，并不代表不可达。

可以用手机操作吗？

介绍页可以手机浏览，但完整分析建议在桌面浏览器中进行，以获得更好的地图交互体验。

仓库结构

baidu-map/
  life-circle-algorithm/   可安装的 Python 包 life_circle
  backend/                 FastAPI 应用
  life-circle-demo/        React 工作台
  data/osm/                OSM 图缓存与边界
  data/water-reviews/      水系复核
  docs/                    项目级说明

三者的依赖方向是固定的：

  • life_circle 不认识 HTTP、体检或前端，提供共享模型与工具。
  • backend 以可编辑安装依赖这个包，再在 app/ 里实现产品。
  • 前端不装算法包，只通过 HTTP 契约说话。

生产成圈不走历史自适应网格。线上百度边界搜索走 backend/tools/endpoint_multicross_boundary.py，由 app/algorithms/baidu_e82.py 适配成任务结果。

运行时总览

一个进程、一个 worker。任务管理器、限流门和内存中的旧任务都假设单进程；多 worker 会把配额和并发限制拆成多份。

app/main.py 的 create_app 是唯一装配点：

  1. load_settings() 读 backend/.env，进程环境变量优先。
  2. 建一个 Quota，方向门和地点门分开，全应用共用。
  3. 建 AnalysisManager 和 HybridManager，与体检共用方向门。
  4. 建 LazyOsmOfflineEngine，启动时不加载全市图，首次使用时惰性加载。
  5. build_checkups 打开体检库、注册两个引擎、注入 Quota。
  6. 开始对外服务时才 interrupt_unfinished()，把上次没跑完的体检标成中断，不重放已付费请求。

三条入口，三套契约

请求点名算法。服务端不会在引擎失败时静默换另一套，也不会接受对方的请求体。

入口谁在用引擎
POST /api/v2/checkups当前页面baidu_e82 或 osm_hybrid
POST /api/analyses旧接口，页面已不走E8.2 核心
POST /api/v1/analysis/hybrid旧接口Hybrid v1.5

错误信封也按路径分开。校验失败不回显原始输入、URL 或密钥。

体检 v2：主路径

编排在 app/checkups/manager.py。同一时刻只跑一个任务，第二个排队而不是 409。任务级截止约 1800 秒。

一次运行按阶段发布不可变修订。已付费的阶段结果在取消时仍然冻结，不丢弃。

阶段做什么
成圈调用引擎 compute-only 接缝，得到 IsochroneSnapshot
设施在冻结圈面上检索、分类、去重
评估用全市步行图做 1000 米服务场
核验120 次路线预算抽检
报告复述已冻结的评估与核验，不重算

两套成圈引擎

百度边界搜索 baidu_e82

  • 标识：algorithm=local-multicross-e82，默认档位 400。
  • 调用链：BaiduE82Engine.compute → tools/endpoint_multicross_boundary.py。
  • 证据来自百度实际返回的路线端点，不来自合成端点。
  • 不需要 OSM 图才能成圈。质量不会高于 partial。

OSM＋百度 osm_hybrid

  • 核心在 app/algorithms/hybrid_isochrone/，版本 v1.5。
  • 档位 200 / 400，计算域默认投影平面上 ±1200 米正方形。
  • 调用链：惰性加载全市图 → OsmGuidance 采样引导 → 百度步行核验 → 成面并扣除水体。
  • 缺图、版本不符时就绪项标 degraded 并降低质量。

共享基础设施

配额

方向服务和地点服务各有门、各有日预算，日界是 Asia/Shanghai。账本在 backend/.quota/quota.sqlite3。

坐标

线上几何一律是 BD09LL，经度在前，不是 WGS84 GeoJSON。米制计算用 EPSG:32651（上海）。

设施目录与距离规则

类别字典在 app/categories.json。距离规则在 app/service_rules.py。900 秒是成圈阈值；1000 米是设施服务标准。二者不是同一个数。

缓存

地点分页、路线和空间结果的跨任务复用由 cache_freshness_seconds 控制。未配置时缓存只在写入它的那个任务内复用。

前端

生产入口是 src/main.tsx。地址是 hash，不是 History API：#/checkup/e82、#/checkup/hybrid。

  • client.ts 只讲 /api/v2，每个响应先过校验。
  • controller.ts 负责提交、轮询、按修订取图层、取消和恢复。
  • sessions.ts 让控制器活在模块里，不活在组件里。
  • CheckupApp.tsx 只排版，能选什么、数字怎么读、画成什么都是纯函数。

数据与进程边界

路径内容重启后
backend/.checkups/体检元数据和已发布修订未完成任务标中断；已发布修订保留
backend/.quota/本应用日消耗保留
data/osm/PBF、图缓存、障碍与风险启动时不读；首次使用才加载

部署约定：--workers 1。

改哪里

要改的事先看
加或换成圈算法实现 IsochroneEngine，在 build_registry 注册
改 E8.2 采样backend/tools/endpoint_multicross_boundary.py
改 Hybridapp/algorithms/hybrid_isochrone/
改服务覆盖app/accessibility/ + app/scoring.py
改设施类别app/categories.json
改体检阶段app/checkups/manager.py
改配额app/quota.py
改页面life-circle-demo/src/checkup/

不要打破的不变量

  • 两套引擎不是彼此的降级，请求、档位、失败都不能改道。
  • 三套 HTTP 契约不能混用字段。
  • displayGeometry 只用于描边。
  • 阶段未就绪用具名拒绝，不用空几何冒充「没有」。
  • 检索失败、分页截断和零结果是三种状态。
  • 圈外邻近设施不能计入圈内数量。
  • 业务状态不以 complete 表示目录已核全。
  • 全应用只有一对百度限流门。
  • 日志和错误响应不记录 AK、完整 URL 或异常原文。
